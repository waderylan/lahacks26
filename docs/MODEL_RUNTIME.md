# Evaluation and frozen experiments

- Explore chooses Jev or Qwen explicitly. Each saved rule records its own provider and evaluator identity. Editing the provider requires saving a new revision before actions run. Page model changes preserve the selected company, current search and unsaved rule; they do not override saved rules.
- Rules added from starters record the selected provider. Background checks, manual runs and preview use the recorded policy. A changed deployment, inference policy or score configuration requires resaving a rule; an in-flight change applies no actions.
- New rule-action snapshots and run summaries freeze provider, model/deployment, policy version and score-configuration identity. Earlier history remains readable as **unknown evaluator**. The historical training README's provenance claim applies only to new runs after this implementation; older archived runs did not capture that evidence.
- Qwen's settled decision may have no score. The UI says **Score unavailable**. Raw candidate scores and validation-adjusted scores are labelled separately; neither is a validated probability for the four-company review dataset. Invalid outputs remain errors, not nonmatches. Jev probabilities keep their own label.
- Runtime configuration uses environment variables or `MODEL_CONFIG_FILE` (see `config/models.example.json`). `VERI_DEPLOYMENT_ID`, `VERI_MODEL_NAME` and `QWEN_CALIBRATION_FILE` override manifest values. Calibration paths in the manifest are relative to that manifest. Runtime does not read the training archive to discover deployment or calibration settings. Keys remain environment-only.
- Calibration must match the deployment and have finite coefficients, a nonnegative slope, at least 100 validation examples, and the documented authored-validation source. `QWEN_RAW_SCORES=1` disables adjustment. Calibration coefficients/source identity and raw mode version both server and client caches. Requests freeze their configuration before waiting for a model slot.
- Existing training artifacts remain unchanged as experiment evidence. Reproduce the frozen input population and overlay cases with `npx tsx scripts/prepare_semantic_training.ts --out artifacts/preparations/overlay-v1`. Add `--teacher` for the existing 200 unreviewed teacher examples: 800 overlay cases versus 1,000 assembled training examples. This command calls no models and starts no training job.
- Preparation uses the frozen 70/15/15 original-company manifest and immutable case files, independent of the synthetic-only runtime. It copies source files, records hashes, validates company separation and writes only to a new or empty directory outside the training archive. Existing output directories are never overwritten. Reproduction uses frozen contexts, so original raw-data downloads are not needed.
- The earlier benchmark/teacher collection scripts are live experiment tools, not automated verification. They were not run. Existing benchmark results do not establish accuracy on document-rich companies 101–104.
